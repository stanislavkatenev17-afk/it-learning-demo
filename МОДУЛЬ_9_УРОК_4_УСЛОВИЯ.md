## 1. Когда следующий шаг зависит от правила

Представьте учебную программу для набора группы. В ней задано количество участников, а правило такое: для готовности группы нужно минимум три человека.

При двух участниках программа должна сообщить, что людей пока недостаточно. При трёх или четырёх — что группа готова. Количество в каждом примере заранее известно; искать настоящих участников и пользоваться сервисом не требуется.

Пока мы читали простую последовательность, каждая следующая строка выполнялась по порядку. Теперь появляется выбор: следующее действие зависит от результата проверки.

В модуле 8 уже были проверки названия и права действия. Но похожая ситуация ещё не объясняет, как записан выбор внутри программы. Здесь разберём его с начала: правило, сравнение, логический результат и одна из двух групп инструкций.

После урока вы сможете проследить такой выбор в коротком фрагменте Python и проверить значение на точной границе правила. Все новые знаки объясним до применения; запуск не требуется.

**Проверьте себя.** Правило «минимум три участника» допускает готовность группы, в которой ровно три человека?

**Ответ:** да. «Минимум три» означает три или больше. Ровно три входит в разрешённый диапазон.

## 2. Как записать сравнение

В 9.3 имя `count` обозначало количество. Теперь будем использовать его для количества участников. Это новое отдельное выполнение, а не продолжение примера с карточками.

**Сравнение сопоставляет значения по заданному правилу.** Для нашего правила нужен знак `>=`: «больше или равно». Два символа читаются вместе, между ними нет пробела.

Тогда выражение `count >= 3` означает: «Текущее количество больше трёх или равно трём?»

| Количество | Проверка | Результат словами |
|---|---|---|
| 2 | Два больше трёх или равно трём? | Ложь |
| 3 | Три больше трёх или равно трём? | Истина |
| 4 | Четыре больше трёх или равно трём? | Истина |

Сравниваются числовые значения. Нам пока не нужны сравнения текстов и других видов данных.

**Условие** в примере этого урока — проверка, результатом которой является истина или ложь. Само выражение сравнения подходит на роль такого условия.

**Проверьте себя.** При `count`, равном 2, определите результат `count >= 3` и обоснуйте его сравнением двух чисел.

**Ответ:** Результат — `False`: 2 меньше 3, поэтому проверка «больше или равно трём» даёт ложь. При затруднении проговорите сравнение словами.

## 3. Что получается после проверки

В прошлом уроке мы познакомились с логическими значениями. В Python истина записывается как `True`, ложь — как `False`.

Теперь получим одно из них сравнением:

```python
count = 3
print(count >= 3)
```

Первая строка присваивает имени число 3. Во второй сначала вычисляется сравнение: 3 больше или равно 3, значит результат — `True`. Затем `print` показывает этот логический результат.

Ожидаемый вывод:

```text
True
```

Сравнение не присваивает `count` другое число. До него количество было 3 и после него остаётся 3.

Для независимого варианта с первой строкой `count = 2` тот же показ выдаст `False`. Мы меняем исходное количество и заново разбираем пример; значения не переносятся скрытно из другого выполнения.

Проверка и действие после неё различаются. Пока мы только получили и показали логический результат. Выбор сообщения о группе ещё не записан.

**Проверьте себя.** Сравнение `count >= 3` само заменяет текущее значение `count` на число 3?

**Ответ:** нет. Оно даёт логический результат проверки. Изменение значения имени задаётся присваиванием, а не этим сравнением.

## 4. Как указать действие для истинного условия

**Ветвление — выбор следующего действия по результату условия. Ветвь — группа инструкций выбранного варианта.**

Для записи варианта «если условие истинно» используется слово Python `if`, которое читаем как «если». После него записывается условие, затем двоеточие `:`. Двоеточие здесь — часть правил языка: оно начинает описание группы инструкций.

**Отступ — пробелы в начале строки, показывающие её принадлежность группе.** В наших примерах перед инструкцией внутри ветви ставим четыре пробела. Это не просто способ сделать текст красивее: отступ участвует в определении структуры программы.

Сообщение «Группа готова» — обычный текст. Прямые двойные кавычки задают его границы, как в 9.3. Все элементы следующей записи теперь объяснены:

```python
count = 3
if count >= 3:
    print("Группа готова")
```

| Часть | Назначение |
|---|---|
| `if` | Начать выбор по условию |
| `count >= 3` | Получить логический результат сравнения |
| `:` | Начать группу инструкций |
| Четыре пробела перед `print` | Показать, что инструкция входит в эту ветвь |
| `print("Группа готова")` | Показать заданный текст |

При 3 условие истинно, поэтому сообщение будет показано. Если в независимом варианте количество равно 2, инструкция с отступом будет пропущена. В этом коротком варианте другого сообщения пока нет, вывод будет пуст.

Важно: мы не требуем от читателя угадать смысл английского слова или двоеточия. Каждая часть записи имеет указанную роль.

**Проверьте себя.** Четыре пробела перед `print` здесь только украшают строку и ни на что не влияют?

**Ответ:** нет. Отступ показывает, что эта инструкция относится к ветви `if` и выполняется при истинном условии. Произвольное изменение отступов может изменить структуру или сделать запись недопустимой.

## 5. Как добавить вариант «иначе»

Теперь зададим действие и для ложного результата.

Слово `else` читаем как «иначе». В нашей паре оно указывает вторую ветвь — для случая, когда условие после `if` ложно. После `else` тоже ставится двоеточие, а его инструкции записываются с отступом.

`if` и `else` начинаются на одном уровне. Инструкции внутри обеих ветвей имеют одинаковый отступ — четыре пробела.

```python
count = 3
if count >= 3:
    print("Группа готова")
else:
    print("Нужно больше участников")
```

При 3 выполняется первая ветвь, при 2 — вторая. В этой конструкции выбирается ровно одна из них. После выполнения первой ветви программа не начинает автоматически выполнять вторую.

```text
Проверить count >= 3
        ├─ истина → показать «Группа готова»
        └─ ложь   → показать «Нужно больше участников»
```

Стрелки поясняют выбор; это схема, а не дополнительная запись Python. Сама проверка в этом примере не печатает `True` или `False`: для неё отдельный `print` не задан. Показывается сообщение выбранной ветви.

**Проверьте себя.** В конструкции `if`/`else` условие истинно. Укажите выбранную ветвь и объясните, что происходит с другой ветвью этой пары.

**Ответ:** Выполняется ветвь `if`. Ветвь `else` в этой паре пропускается, а не становится следующим обязательным действием. При затруднении проследите один выбранный путь.

## 6. Что выполняется после выбора

Добавим сообщение, которое нужно показать после любой выбранной ветви: «Проверка завершена».

Чтобы оно не относилось к одной ветви, запишем его после обеих ветвей без отступа — на том же уровне, что `if` и `else`.

```python
count = 3
if count >= 3:
    print("Группа готова")
else:
    print("Нужно больше участников")
print("Проверка завершена")
```

Последняя инструкция продолжает общую последовательность. В наших примерах нет ошибок и других действий, прерывающих работу, поэтому после выбранной ветви исполнение до неё доходит.

При количестве 3 ожидаемый вывод:

```text
Группа готова
Проверка завершена
```

Для независимого варианта с количеством 2:

```text
Нужно больше участников
Проверка завершена
```

| Момент при количестве 3 | Что происходит | Текущий вывод |
|---|---|---|
| После присваивания | `count` обозначает 3 | Пусто |
| После сравнения, до ветви | Получена истина | Пусто |
| После выбранной ветви | Показано сообщение готовности | Группа готова |
| После общего шага | Показано завершающее сообщение | Группа готова → Проверка завершена |

Стрелка в таблице разделяет строки вывода и сама не печатается. Вторая ветвь не выполнялась, поэтому её сообщение в таблицу не добавлено.

**Проверьте себя.** Последняя строка без отступа выполняется только при истинном условии?

**Ответ:** нет. В этом фрагменте она выполняется после любой выбранной ветви. Она стоит за всей конструкцией выбора, а не внутри первой ветви.

## 7. Как отличить присваивание от равенства

В 9.3 одиночный `=` задавал присваивание. Для проверки равенства в Python используются два знака подряд: `==`.

`count == 3` означает «Текущее значение `count` равно 3?» Это сравнение даёт истину или ложь и само не меняет значение имени.

Разберём отдельный пример:

```python
count = 2
print(count == 3)
print(count)
```

Первая строка задаёт значение 2. Следующая проверяет равенство с 3 и показывает `False`. Последняя показывает прежнее 2, потому что сравнение его не изменило.

```text
False
2
```

| Запись | Действие |
|---|---|
| `count = 3` | Связать имя с числом 3 |
| `count == 3` | Проверить, равно ли текущее значение числу 3 |
| `count >= 3` | Проверить, больше ли текущее значение трёх или равно ему |

Два сравнения также различаются между собой. Для 4 выражение `count >= 3` истинно, а `count == 3` ложно. Первое допускает значения выше границы, второе — только точное равенство.

**Проверьте себя.** В независимом примере `count` равно 2. Укажите результат `count == 3` и значение `count` после сравнения.

**Ответ:** Сравнение даёт `False`, значение `count` остаётся 2. Для изменения имени нужно присваивание; проверка равенства его не выполняет.

## 8. Зачем проверять границу и смысл правила

Для правила «минимум три» полезно проверить хотя бы три случая: меньше границы, ровно на границе и больше границы. В нашем примере это 2, 3 и 4.

Так легче заметить ошибку, при которой ровно три человека ошибочно считаются недостаточным количеством. Здесь знак `>=` подходит требованию: он включает равенство.

Но правильный выбор по одному правилу не означает, что проверено всё приложение. В модуле 8 отдельно рассматривались содержание названия, право действия, выполнение записи и получение подтверждения.

Наша учебная программа проверяет только количество. Она не устанавливает личность участников, не проверяет права в «Полке», не резервирует места и не сохраняет список группы. Ни один из этих результатов не следует из показанного текста «Группа готова».

```text
Конкретное правило: количество не меньше 3
                    ↓
Выбор сообщения по этому правилу

Другие проверки и запись данных здесь не заданы.
```

Слово «условие» тоже требует контекста. В условии учебного задания могут быть описаны многие правила и исходные данные. В программной записи этого урока условие — конкретная проверка, по результату которой выбирается ветвь.

**Проверьте себя.** Достаточно ли добавить такую проверку количества, чтобы заменить все серверные проверки «Полки» и подтвердить запись данных?

**Ответ:** нет. Она проверяет только заданное числовое правило. Остальные проверки, взаимодействие с базой и подтверждение результата — отдельные действия.

## 10. Практика по описанию: три независимых входа

**Цель:** проверить обе ветви, точную границу и общий шаг после выбора.

### Условие

Используйте полный пример из части 6:

```python

    print("Группа готова")
else:
    print("Нужно больше участников")

```

Рассмотрите его отдельно для начального количества 2, 3 и 4. Для этого в каждом варианте меняется только число первой строки. Каждый вариант начинается заново с пустым выводом, без скрытых вводов, других изменений, ошибок и сохранений.

### Задание

2. Запишите весь вывод по порядку.
3. Назовите конечное значение `count`.
4. Отдельно оцените `count == 3` для каждого входа. Это дополнительный вопрос по состоянию, а не новая инструкция показа в программе.

Ничего запускать не нужно. Можно заполнять таблицу на бумаге или отвечать устно.

### Образец результата

| Вход | `count >= 3` | Ветвь | Полный вывод по порядку | Конечное `count` | Отдельно: `count == 3` |
|---|---|---|---|---|---|
| 2 | `False` | `else` | Нужно больше участников → Проверка завершена | 2 | `False` |

Значение `count` не изменилось после выбора, потому что в ветвях только показ текста, а нового присваивания нет. При 4 первая проверка истинна, но отдельная проверка точного равенства трём ложна.

- В каждом варианте показаны две строки: одна из ветви и одна общая.
- Ни один вариант не выводит оба сообщения ветвей.
- Сравнения не меняют исходное количество.
- Дополнительная проверка равенства не добавлена к выводу программы.

## 11. Что стоит запомнить и куда идём дальше

Условие в нашем примере даёт логический результат. Конструкция `if`/`else` использует его для выбора одной из двух ветвей. Отступы показывают, какие инструкции принадлежат выбранному варианту, а какая строка выполняется после всего выбора.

Присваивание `=` и сравнение `==` решают разные задачи. Проверка `>=` включает равенство, поэтому точную границу полезно разбирать отдельно.

Мы научились выбирать действие. В следующем уроке научимся повторять одну группу инструкций для нескольких заданных значений. Для этого отдельно введём список и цикл, не требуя заранее знать их запись.

## Словарь урока

- **Сравнение** — сопоставление значений по заданному правилу.
- **Условие** в примере урока — проверка, результат которой является истиной или ложью.
- **Ветвление** — выбор следующего действия по результату условия.
- **Ветвь** — группа инструкций выбранного варианта.
- **Отступ** — пробелы в начале строки, показывающие принадлежность группе инструкций.
- **`if`** — начало выбора по условию, читаем «если».
- **`else`** — ветвь для ложного результата условия в рассматриваемой паре, читаем «иначе».

## Редакторские заметки и основания

Восемь коротких проверок, четыре итоговых вопроса и одна практика соответствуют карточке. Последовательность: правило словами → сравнение `>=` → логический результат → `if`, двоеточие и отступ → `else` → общая инструкция → отличие `=` от `==` → граница и пределы правила. Все слова сообщений — строки, объяснённые в 9.3. Промежуточный пример без `else` в части 4 явно ограничен и затем заменён полной парой.

Правила сверены по [Python Tutorial: if Statements](https://docs.python.org/3/tutorial/controlflow.html#if-statements), [Python: Comparisons](https://docs.python.org/3/library/stdtypes.html#comparisons) и [Language Reference: Indentation](https://docs.python.org/3/reference/lexical_analysis.html#indentation). Логические значения уже введены в 9.3. Используются только сравнения целых; истинность произвольных объектов, составные условия, `elif` и вложенные ветви не изучаются.

Основной пример и три входа практики не продолжают фрагменты предыдущих частей. Само сравнение не выдаёт вывод, если не помещено в `print`, как в частях 3 и 7. Все обычные ветви доходят до общего показа; аварийное завершение исключено условиями. Дополнительное сравнение в практике не добавлено строкой программы.

Ответы сверены вручную; Python не найден среди доступных команд среды, локального исполнения не было. Проверки права и записи из модуля 8 не заменяются учебным правилом количества. 9.4 не требует ещё не введённых циклов и функций; переход к 9.5 подготовлен. Видео и проверки на учениках не было.
