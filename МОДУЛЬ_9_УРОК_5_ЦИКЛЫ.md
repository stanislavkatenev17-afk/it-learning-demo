## 1. Когда одинаковое действие нужно несколько раз

Есть три заданных количества: 2, 1 и 3. Нужно получить их общую сумму. Можно сначала прибавить 2 к нулю, затем прибавить 1, затем 3. На каждом шаге действие похоже: взять очередное число и добавить его к уже полученной сумме.

Если чисел окажется больше, вручную описывать отдельную инструкцию для каждого неудобно. Вместо этого можно задать правило повторения.

**Цикл — конструкция, задающая повторное выполнение группы инструкций по определённому правилу.** Здесь будем выполнять одну и ту же группу для каждого значения из небольшого заданного набора.

В прошлом уроке условие помогало выбрать действие. Цикл решает другую задачу: повторить действие по установленному правилу. В этом уроке выбор внутри повторения пока не нужен.

Сначала объясним, как записан набор значений, затем — как брать очередное значение. После этого проследим изменение общей суммы. Все задания выполняются по описанию, без установки и запуска Python.

**Проверьте себя.** Чтобы сложить большее количество значений, обязательно вручную писать отдельную строку сложения для каждого из них?

**Ответ:** нет. Можно задать повторяемое действие и правило, по которому оно применяется к очередным значениям. Для этого в примере используем цикл.

## 2. Как записать несколько значений

**Список Python — упорядоченный набор элементов. Элемент — одно значение в этом наборе.** Порядок означает, что можно различить первое, следующее и последнее значения.

Для записи списка используем квадратные скобки `[` и `]`. Между элементами ставятся запятые. В нашем примере запятая разделяет целые значения, а не обозначает дробную часть числа.

```python
[2, 1, 3]
```

| Часть записи | Значение |
|---|---|
| `[` и `]` | Границы списка |
| `2`, `1`, `3` | Три элемента по порядку |
| Запятые | Разделители элементов |
| Пробелы после запятых | Помогают читать запись |

Это не число 213. Это три отдельных целых значения: сначала 2, затем 1, затем 3.

Одинаковые значения могут встречаться несколько раз. В `[2, 2]` два элемента, хотя оба равны 2. Для общей суммы нужно учесть оба.

В модуле 8 встречались список на экране и таблица базы. Сейчас слово «список» обозначает конкретный способ организации данных в Python. Внешне похожие представления не объявляются одним и тем же объектом.

**Проверьте себя.** Для списка `[2, 2]` укажите количество элементов и объясните, как учитываются совпадающие значения.

**Ответ:** Элементов два. Каждый занимает своё место в списке и участвует в обходе; совпадение значений не объединяет их в один элемент.

## 3. Как получить очередной элемент

Для обхода нашего списка используем слова Python `for` и `in`. Вместе в этой записи читаем их как «для каждого элемента в списке».

Между ними стоит имя `item`. Его выбрал автор; оно означает «элемент». При очередном повторении с этим именем связывается очередное значение списка.

Начало записи выглядит так:

```python
for item in [2, 1, 3]:
```

Это ещё не полный фрагмент: после такой строки должна идти повторяемая группа инструкций. Сейчас разбираем только её начало.

Знакомое двоеточие `:` открывает группу. В последовательном обходе данного списка имя `item` получает значения 2, затем 1, затем 3.

**Итерация — одно прохождение повторяемой группы инструкций.** В этом уроке на каждой итерации обрабатывается очередной элемент. Для трёх элементов будет три таких прохода.

| Проход по счёту | Значение `item` в нём |
|---|---|
| Первый | 2 |
| Второй | 1 |
| Третий | 3 |

Номер прохода и значение элемента различаются. На первом проходе `item` равно 2, а не 1. Имя получает само значение из списка, не его порядковый номер.

**Проверьте себя.** На первом проходе по `[2, 1, 3]` значение `item` будет 1, потому что это первый проход?

**Ответ:** нет. Первое значение списка — 2, поэтому `item` обозначает 2. Число 1 как значение появится на втором проходе.

## 4. Какие инструкции повторяются

**Тело цикла — повторяемая группа инструкций.** Как и в конструкции выбора, её принадлежность показывается отступом. В наших примерах используем четыре пробела перед строками тела.

Возьмём уже знакомый показ через `print` и соберём полный фрагмент:

```python
for item in [2, 1, 3]:
    print(item)
print("Конец")
```

Строка с отступом показывает текущий элемент. Она выполнится на каждом проходе. Последняя строка без отступа находится после цикла и выполнится один раз, когда обход закончится.

Ожидаемый вывод:

```text
2
1
3
Конец
```

Сообщение «Конец» — обычная строка в кавычках; она не управляет завершением сама по себе. В этом фрагменте после последнего показа других инструкций нет.

```text
Взять очередной элемент → выполнить тело → перейти к следующему
После обхода всех элементов → выполнить инструкцию без отступа
```

Это описание правил данного обхода. Не нужно считать, что последняя строка входит в тело только потому, что записана рядом с ним.

**Проверьте себя.** В этом примере сообщение «Конец» покажется после каждого числа?

**Ответ:** нет. Его `print` расположен без отступа после цикла, поэтому выполнится один раз после всех трёх проходов.

## 5. Как подготовить общую сумму

Теперь вместо показа каждого элемента будем обновлять общую сумму.

Выберем имя `total`, которое означает «общая сумма». **Накопление — обновление общего результата по мере обработки элементов.** До первого прохода сумма равна 0: ни одного числа ещё не прибавили.

Присваивание `total = 0` задаёт исходное значение. В теле строка `total = total + item` использует правила из 9.3: сначала читает прежнюю сумму и текущий элемент, складывает их, затем присваивает новую сумму тому же имени.

```python
total = 0
for item in [2, 1, 3]:
    total = total + item
print(total)
```

Все новые элементы уже разобраны. `total = 0` стоит до цикла и выполняется один раз. Инструкция сложения имеет отступ и повторяется. Итоговый показ стоит после цикла.

Если начальное значение `total` не задано, при первом сложении нельзя прочитать известную прежнюю сумму. Поэтому её не нужно угадывать или считать нулём автоматически.

Если же поместить сброс к нулю внутрь каждого прохода перед сложением, получится другой способ: прежний накопленный результат будет теряться. В нашем примере сброс стоит только до цикла.

**Проверьте себя.** Можно ли удалить `total = 0` и молча считать, что на первом проходе программа сама возьмёт ноль?

**Ответ:** нет. Правая часть присваивания использует уже известное значение `total`. В новом выполнении его нужно явно задать до чтения.

## 6. Что меняется на каждом проходе

Проследим основной пример из части 5. В начале `total` равно 0.

Первый элемент — 2. Вычисляется 0 + 2, новая сумма — 2. Второй элемент — 1. Используется уже сумма 2: получается 2 + 1, то есть 3. Третий элемент — 3. Получается 3 + 3, то есть 6.

| Проход | `item` | `total` до сложения | Вычисление | `total` после |
|---|---|---|---|---|
| Первый | 2 | 0 | 0 + 2 | 2 |
| Второй | 1 | 2 | 2 + 1 | 3 |
| Третий | 3 | 3 | 3 + 3 | 6 |

Сумма не заменяется просто текущим элементом. Для этого понадобилось бы другое действие. Здесь к прежнему общему значению прибавляется очередное число.

Таблица показывает именно значения для данного выполнения, а не разные независимые варианты. Каждый следующий проход использует итог предыдущего.

```text
Начало: 0 → прибавить 2: стало 2 → прибавить 1: стало 3 → прибавить 3: стало 6
```

**Проверьте себя.** В примере накопления после первого прохода сумма равна 2. На втором `item` равно 1. Назовите прежнюю сумму, добавляемое значение и новую сумму.

**Ответ:** Прежняя сумма 2, добавляемое значение 1, новая сумма 3. Новая сумма не заменяется одним текущим элементом. При затруднении используйте значение, оставшееся после прошлого прохода.

## 7. Почему вычисленное не обязательно показано

В основном примере внутри тела нет `print`. Там меняется только сумма. Поэтому промежуточные 2 и 3 не появляются в выводе.

После завершения обхода выполняется `print(total)`. К этому моменту `total` равно 6, и показывается одно число:

```text
6
```

| Момент | Текущая сумма | Весь вывод |
|---|---|---|
| До цикла | 0 | Пусто |
| После первого прохода | 2 | Пусто |
| После второго прохода | 3 | Пусто |
| После третьего прохода | 6 | Пусто |
| После итогового `print` | 6 | 6 |

Это продолжает различие из 9.2–9.3: вычисление, присваивание и показ — разные действия. Если значение можно прочитать в таблице разбора, это ещё не означает, что программа его вывела.

Итоговый показ также не подтверждает запись в файл или базу. В примере нет действий с накопителем, сетью или «Полкой».

**Проверьте себя.** В основном примере получены промежуточные суммы 2, 3 и 6, а единственный `print` стоит после цикла. Запишите полный вывод и объясните его состав.

**Ответ:** В выводе только 6. Промежуточные суммы менялись присваиванием, но их показ не задавался. При затруднении найдите расположение единственного `print`.

## 8. Когда повторение заканчивается и может ли его не быть

В нашем обходе для каждого элемента заданного списка тело выполняется один раз. Когда элементы заканчиваются, программа переходит к следующей инструкции после цикла. Сам список во время этих примеров не меняется.

**Пустой список — список без элементов.** Его запись — `[]`: между квадратными скобками нет значений.

Рассмотрим независимый вариант с начала:

```python
total = 0
for item in []:
    total = total + item
print(total)
```

Очередного элемента нет уже в начале. Тело не выполняется ни разу, сумма остаётся 0. Затем показ после цикла выдаёт:

```text
0
```

В этом варианте имя `item` не получило значения. Это не мешает примеру: тело не выполняется, а после цикла читается только заранее заданное `total`. Мы не пытаемся прочитать отсутствующий текущий элемент.

Не всякое повторение обязательно происходит хотя бы раз. И завершение любого возможного цикла из нашего примера тоже не следует: существуют другие правила повторения. Сейчас достаточно знать, почему заканчивается этот обход конечного списка, который не изменяется во время работы.

```text
Есть следующий элемент?
  да → получить его → выполнить тело → вернуться к вопросу
  нет → перейти к инструкции после цикла
```

В модуле 8 поиск в базе не был объявлен обязательным перебором всех строк. Наш цикл — отдельный учебный способ работы с заданным списком, а не описание внутренней работы любой СУБД.

**Проверьте себя.** Любой цикл обязательно делает хотя бы один проход, а потом всегда заканчивается?

**Ответ:** нет. Пустой список в нашем примере даёт ноль проходов. Завершение здесь объясняется конечным набором, который не меняют во время обхода; на любые другие правила повторения этот вывод не переносится.

## 9. Проверим понимание

**Вопрос 1.** Сколько проходов даст обход списка `[2, 2]`, если тело выполняется для каждого элемента?

**Вопрос 2.** Какие значения получает `item` при обходе `[2, 1, 3]`? Это значения или номера позиций?

**Вопрос 3.** Что целиком покажет основной пример с накоплением суммы из части 5?

**Вопрос 4.** Что получится в нём при замене списка на `[]` и новом начале с `total = 0`?

### Ответы и объяснения

1. **Два прохода.** Элементов два, совпадение значений их не объединяет. Повторите часть 2.
2. **2, затем 1, затем 3 — значения элементов.** Первое значение не обязано быть 1; номер прохода — отдельная характеристика разбора. Повторите часть 3.
3. **Только число 6.** В теле получены суммы 2, 3, 6, но показ задан один раз после цикла. Повторите части 5–7.
4. **Покажется 0.** Тело не выполнится, начальная сумма сохранит значение. Общая инструкция показа после цикла выполнится один раз. Повторите часть 8.

## 10. Практика по описанию: одинаковые элементы тоже учитываются

**Цель:** проследить накопление суммы и правильно разобрать пустой вход.

### Условие

Первый вариант — отдельное выполнение с начала:

```python
total = 0
for item in [1, 3, 1]:
    total = total + item
print(total)
```

Второй вариант независим: заменить список на `[]`, остальное оставить и вновь начать с `total = 0`. Списки не изменяются в процессе, скрытых вводов и действий нет. Запуск не требуется.

### Задание

1. Назовите количество проходов в каждом варианте.
2. Для каждого состоявшегося прохода запишите текущий элемент, прежнюю и новую сумму.
3. Укажите полный вывод каждого варианта.
4. Объясните, почему нельзя пропустить повторное вхождение 1 — третий элемент списка.

### Образец результата

| Проход первого варианта | `item` | Прежняя сумма | Новая сумма |
|---|---|---|---|
| Первый | 1 | 0 | 1 |
| Второй | 3 | 1 | 4 |
| Третий | 1 | 4 | 5 |

В первом варианте три прохода, после цикла показано только 5. Повторная 1 стоит на третьей позиции списка. Это отдельный элемент, который должен участвовать в сумме, как и первая 1.

Во втором варианте проходов нет, начальная сумма остаётся 0 и после цикла показывается только 0. Данные первого варианта не переносятся во второй.

### Самопроверка

- Начальная сумма задана до цикла и не сбрасывается внутри.
- Для первого списка получены суммы 1, 4, 5.
- Учтены оба элемента со значением 1.
- В каждом варианте показано одно итоговое число, а не промежуточные суммы.
- Пустому списку не добавлен выдуманный проход.
- Имя текущего элемента после пустого обхода не читается.

Если трудно, повторите части 3–7. Для каждого элемента начните с суммы, оставшейся от предыдущего прохода. Для пустого списка вернитесь к части 8 и сразу перейдите к инструкции после цикла.

## 11. Что стоит запомнить и куда идём дальше

Цикл задаёт повторяемую группу инструкций. В нашем `for` текущему имени по очереди передаются значения списка, а тело выполняется для каждого элемента. Отступ отделяет повторяемые инструкции от последующего общего шага.

При накоплении суммы нужно задать начальное значение и использовать результат предыдущего прохода. Вычисление промежуточных значений не означает их показ. Для пустого списка проходов нет, но инструкция после цикла остаётся.

В следующем уроке дадим действию имя: опишем его один раз и будем вызывать с разными входными значениями. Для этого с начала введём понятие функции.
