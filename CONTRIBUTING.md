# Совместная работа

## Ветка и PR

1. Получите актуальный main. Создайте отдельную ветку, например `design/lighter-ui`.
2. Правьте исходники в site/src и нужные генераторы схем. Корневые CSS/JS — опубликованный результат; изменение только этих файлов не исправляет исходники.
3. Выполните `node site/build.mjs`, три проверки из README и браузерный просмотр через `node site/serve.mjs`.
4. Создайте PR в main. Опишите проблему и получившееся поведение, затронутые части, приложите широкие/узкие снимки и результаты проверки. Содержательные изменения уроков/заданий укажите отдельно.
5. Владелец просматривает вариант и принимает решение о слиянии. PR не означает автоматической приёмки учебных материалов.

Доступ соавтора выдаётся отдельно по точному GitHub-логину. Этот комплект не отправляет приглашений и не меняет права.

## Проверка в браузере

- Главная, программа, модуль и прямой переход к уроку.
- Урок 1.2: устройство, условное окно и содержание; длинный текст, схемы и раскрываемые пояснения.
- Урок 7.5: «Показать подсказку» и «Начать заново». Сохраняйте ID и средства действующей демонстрации.
- Проверка модуля 1: четыре ответа, результат и объяснения; результат не меняет самоотметки уроков.
- Поиск кнопкой/Ctrl+K и Escape; словарь DNS и карточки.
- Точное копирование исходного примера 5.5 в буфер.
- Три отметки урока: немедленная галочка меню, снятие отметки, прогресс и предупреждение о сбросе при обновлении.
- Ширины 1440, 768, 390 и 320 CSS-пикселей: отсутствие переполнения и обрезания существенных подписей. Это проверка в настольном браузере, не испытание физическим телефоном.
- Клавиатура, видимый фокус, меню/пояснения и отсутствие ошибок клиентского журнала.

Сохранность текста и автоматические проверки не подтверждают понятность для учеников. Непроверенное отмечайте прямо.

## Дополнительная проверка сборщика

```sh
node site/verify-build-output.mjs
```

Проверяет чистую/повторную сборку, сохранение посторонних файлов в архиве и действующего dist при отказе новой сборки. Создаёт временную копию и отчёт внутри локальной папки audit, исключённой из Git. Использует только Node.js.

Текущие проверки закрепляют светлую тему и временный прогресс. Если отдельный будущий этап изменяет эти договорённости, проверки пересматриваются по новой спецификации; не удаляйте их просто ради зелёного результата.

## Обновление GitHub Pages после приёмки

Pages читает **main → /(root)**. При подготовке репозитория действующие 25 файлов сайта сохранены побайтно.

После согласования изменений владелец выполняет из корня:

```sh
node site/build.mjs
node site/verify.mjs
node site/verify-terms.mjs
node site/verify-theme.mjs
node site/update-demo.mjs
```

Последняя команда копирует собранный сайт в корневой опубликованный снимок. Она не заменяет README, учебные Markdown, конфигурацию Git и исходники. Устаревшие/неизвестные файлы автоматически не удаляет; необходимость удаления ресурса отдельно рассматривается в diff.

Проверьте diff: кроме принятых исходников меняются только соответствующие файлы выдачи. Включите согласованный результат в тот же PR либо отдельный принятый коммит. После слияния в main дождитесь успешного Pages в Actions и проверьте **https://stanislavkatenev17-afk.github.io/it-learning-demo/** с прямыми уроками и изображениями. Pages не запускает наш Node-сборщик автоматически: результат сборки включается в коммит.

Не загружайте всю локальную папку проекта вместо выбранных исходников. Зависимости и секреты будущей серверной части не входят в публичный комплект. VPS, вход и постоянный прогресс — отдельный этап.
